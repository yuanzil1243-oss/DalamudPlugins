原实现的主要流程为：新建固定十层组 → 开银箱刷强化 → 正常通关退本 → 验证并删除本任务建立的存档 → 前往兑换 NPC → 根据背包新增聚魔柄逐次扣减强化缓存 → 进入下一轮；入场前也有一次兑换检查。数量为 `min(每批上限, floor((min(武器,防具)-保留值)/10))`，双方均达到门槛才开始该批。

本地版复用方案与元数据，按当前 API 和扩展壳重写接入、缓存及兑换控制器，不覆盖第三方整个引擎或其战斗策略。原有 `FarmingMode` 保持四个取值不变：旧本地配置的 4/5 已被兼容层定义为退役模式，不能追加新的持久化枚举。新功能用默认省略的 `RelicMaterial` 布尔标记、`GripExchange` 可空设置和每个地宫独立的偏好实现，避免旧配置、暂停指纹及普通挖宝偏好被误迁移。

## 运行与异常边界

- 强化缓存按角色和地宫隔离，仅接受副本内存、原生 LogMessage 7250/7252/7253 和已经确认的兑换扣减；不读取玩家聊天。登出或换角色清空，武器／防具分别计时，十分钟过期；只刷新一项不会复活另一项过期读数。迟到的低值日志不能压低当前读数，已确认兑换后日志不能回滚扣减，须下一次副本内存刷新。
- 强化未知或过期时跳过兑换，先走原生入场获取新读数。已知低于保留值时停止并提示。每次提交前重新检查双方读数及保留值。
- 每个会话首次入场前检查一次；每次成功退本后检查一次。首次标记保存在 session，不因下一轮场景重新创建而重置，避免同一组间边界连续兑换两批。
- 只允许本任务新建的存档参与该循环，沿用原有空槽入场、槽位来源验证及删档流程。已有档、当前副本接续、复用准备档不能由本功能获得删除或兑换权限。成功组才计完成轮数；失败不计成功，按原验证清理自建档后重试；用户中止或来源不符时保档停止。
- 删档完成标记跨帧保留，等待兑换期间不会重复删除已经清空的槽位。组末暂停优先于尚未开始的可选兑换；若请求暂停时兑换已经开始，保留其确认和交易回执，先完成本批或明确报错再暂停。取消待生效暂停不销毁进行中的兑换。正常收尾后保存下一轮记录，继续时显式启动，重新读取有效强化。异常组保档暂停。
- NPC 互动由本流程发起后才允许推进对话；角色、职业、目标发生异常变化即停止。菜单要求唯一匹配制作选项；确认框须同时有聚魔柄名称与制作／兑换语义，并排除删除、放弃、带出等语义。只认明确取消项，不把最后一项当取消。
- 一次仅有一份制作回执。发送确认后不可重发；只有背包恰好 +1 才确认一件并扣 10/10。背包增减异常、缺少确认、12 秒无结果或强化缓存无法安全扣减均停止，不重复提交不明交易。兑换总计最多 90 秒，停滞 18 秒停止。
- 副本外前往 NPC 仍使用现有 vnavmesh IPC；没有导航时必须先靠近该 NPC。本功能不改变副本内的导航、战斗、探索及道具策略。
