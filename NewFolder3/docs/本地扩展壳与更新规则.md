当前交付：0.7.55.2103；官方基底：0.7.55.21，提交 a71af60a01682eb76cd6d1ec46ac971b88f75d5a。

## 后续更新流程

按用户约定，每次官方发布新版后，先拉取原作者仓库并固定对应发布提交，再将当前扩展壳套到该官方基底。首个本地修订号使用 01，例如 .21 → .2101；保留原作者新版的副本内战斗、探索、道具策略和奖励实现。构建、回归、源码边界及包内容检查通过后，先交付到 `C:/Users/24496/Documents/ChatGPT/本地插件dll/NewFolder3/测试版本`，等待用户游戏内测试；推送库链另按用户指令执行。

版本字段的上下文变化由工具自动适配；只修改插件清单与工程中的版本字段匹配条件，不放宽代码接入点的上下文检查。出现真正的接入冲突时停止并审阅，不覆盖上游新逻辑。

## 版本约定

最后一段版本号 = 官方最后一段 × 100 + 本地修订号（01–99）。

- 官方 .20 → 第一次修改 .2001，第二次 .2002。
- 官方 .21 → 第一次修改 .2101，第二次 .2102，第三次 .2103。
- 主版本前三段跟随官方；禁止用后缀标签替代 DLL/清单的实际程序集版本。
- `scripts/local_version.py` 是规则实现；构建、审计、打包共同使用该规则。需要本地第二次修订时，更新扩展清单的修订号以及工程/插件清单版本，校验一致后构建。

## 布局与边界

- `LocalExtensions/Host`：内置移速和默认关闭的防踢开关；移速仍由普通层/Boss/过场/副本外/停止等条件控制。
- `LocalExtensions/Core`：已有档保护、继续探索、最高起点、自由探索范围、终局收尾及 GCD 停滞状态机。
- `LocalExtensions/Runtime`：AE 接管租约、独立功能配置、跨模式暂停记录及保档归档。
- `LocalExtensions/Dalamud`：界面/启动适配、离线地图、GCD 观测与单次补打、各模式暂停/继续/解除接入。
- `Directory.Build.targets` 仅引入 `LocalExtensions/LocalExtensions.targets`，后者把对应源文件加入各自的原项目；不把私有功能散落进第三方快照。
- 原作者现有的类不是公共插件扩展 API，因此仍需要少量明确接入点。接入点以 `hooks.patch` 导出。这里不是声称未来任何版本都无需适配。
- 战斗/绕圈/寻路/探索控制器、终局奖励和机制运行时保持官方 .21 原实现；自由探索只在参数与层段决策处接入。`.2103` 将 `FarmingScenario`/`FarmingSession` 设为 partial，并在原决策后及原收尾后各加一个暂停调度调用；`FsdEngine.Pause.cs` 仅接入新锁和新记录继续分派，原版旧记录继续路径保留。入场/出场控制器仍仅保留既有的界面交互间隔调整。
- `FloorWorkPolicy` 的新增分支仅允许自由探索的藏宝选项进入原探索控制器；开箱增强只接入独立运行配置，原开箱算法不变。RunHost 在场景初始化后追加局部配置调用；在原版终局领奖停留分支调用独立扩展策略，开关关闭时保留原行为。

## 生成可复用扩展包

在本工程根目录执行：

```powershell
python scripts/local_overlay.py export --output artifacts/local-overlay-2103
```

结果包括：`hooks.patch`（受限的官方文件接入点）、`additions`（扩展、地图、工具、文档和测试）、`overlay.json`（来源及逐文件哈希）。不含官方私有服务地址、密钥、个人配置或游戏存档。

## 套用下一版官方源码

先在独立的官方源码目录拉取作者更新，然后使用新的输出目录。例：

```powershell
python scripts/local_overlay.py apply --overlay artifacts/local-overlay-2103 --upstream C:/path/to/official-checkout --ref <已核实的官方提交> --revision 1 --output C:/path/to/NewFolder3-next-local
```

工具读取官方版本并计算修改版编号：.20 + revision 2 → .2002；.21 + revision 1 → .2101。

工具克隆指定提交到全新的输出目录，先 `git apply --check` 检查接入点；官方新文件与扩展重名、上下文不匹配或哈希错误时直接停止，不覆盖原工程，不强行套用，也不删除冲突以绕过检查。此时应在新目录审阅差异、更新接入点和测试，再导出新的扩展包。

套用成功只代表源码合成成功。进入新目录初始化依赖并验证：

```powershell
git submodule update --init --recursive
powershell -ExecutionPolicy Bypass -File scripts/Build-Local.ps1
python scripts/test_overlay.py
python scripts/package_local.py --output "C:/Users/24496/Documents/ChatGPT/本地插件dll/NewFolder3/测试版本"
```

只有构建、回归和源码边界审计通过，才生成本地测试包；仍需用户在合适时机切换并进行游戏内测试。工具不安装、不重载、不启动 FSD，不修改库链或发布仓库。

独立模式，按地宫分别保存起止楼层、宝藏、金/银/铜箱、开箱增强和循环偏好。普通新建入口只列原版支持的起点：死宫 1/51，天宫 1/21，朝圣 1/21/31/51/71；实际解锁仍由原生入口确认。

其他十层组起点可通过读取、明确选择对应的已有存档续打；该路径只执行一次并保档停止，不参与删档循环。人物、职业、地宫、槽位、进度和行指纹在启动前重新核验。

完整走完范围才计一轮。例：21–50、3 轮需完成 9 个十层组；中间组不计轮数，失败不计成功。新建任务只清理本任务拥有并验证过的存档，不删除另一槽位。终点是正常组末，不使用诊断停止参数，最终层沿用原奖励验收和退出流程。

## 下底领奖后退本删档循环
